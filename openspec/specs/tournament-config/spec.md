# tournament-config: トーナメント設定(トップページ+エディタ)

## Purpose

トーナメント設定(ストラクチャー・タイトル・プライズ)の作成・検証・IndexedDB への保存と、トップページでの設定一覧・店舗情報(店名)の管理を定める。

## Requirements

### Requirement: 店舗情報(店名)の管理
店名はトーナメント設定ごとではなく、店舗情報として 1 件だけ保持しなければならない(MUST)。トップページ(`/`)は店名を表示し、その場で編集(テキストボックス+キャンセル/保存)できなければならない(MUST)。保存された店名はリロード後も保持されなければならない(MUST)。

店名は必須とし、未入力の間は新規タイマーを作成できてはならない(MUST NOT)。トップページの「新規タイマー作成」は店名が未入力なら店名の入力を促し、エディタへ遷移しない(MUST)。エディタを直接開いた場合も、店名が未入力の間は新規設定の保存をエラーにしなければならない(MUST)。既存設定の編集は店名の有無に関わらず保存できる。

#### Scenario: 店名のインライン編集
- **WHEN** トップページで店名の「編集」を押し、新しい店名を入力して保存する
- **THEN** 見出しとヘッダーの店名表示が更新され、リロード後も新しい店名が表示される

#### Scenario: 編集のキャンセル
- **WHEN** 店名の編集中に「キャンセル」を押す
- **THEN** 入力内容は破棄され、店名は変更されない

#### Scenario: 店名未入力での新規タイマー作成
- **WHEN** 店名が未入力の状態でトップページの「新規タイマー作成」を押す
- **THEN** エディタへ遷移せず、店名の入力欄が開き、先に店名を入力するよう案内が表示される

#### Scenario: 店名未入力でのエディタ直接アクセス
- **WHEN** 店名が未入力の状態で `/editor` を直接開き、新規設定を保存しようとする
- **THEN** 店名が未設定である旨のエラーが表示され、設定は保存されない

#### Scenario: 旧データからの引き継ぎ
- **WHEN** 店名を設定ごと(shopName)に保持していた旧バージョンのデータでアプリを開く
- **THEN** 最終更新の設定の店名が店舗情報として引き継がれる

### Requirement: トップページの設定一覧
トップページ(`/`)は、保存済みのタイマー設定を更新日時の新しい順に一覧表示しなければならない(MUST)。各設定に対して開始(ペアリングモーダルを開く。realtime-pairing 参照)・編集(エディタへ)・複製・削除の操作を提供しなければならない(MUST)。削除は確認ダイアログを経なければならない(MUST)。設定が 1 件もない場合は、新規作成への案内を表示しなければならない(MUST)。

進行中のセッション(直近に開始し、優勝確定・終了していないトーナメント)がある設定には、「開始」(はじめから)に加えて「再開」(保存された進行状態から続行)を表示しなければならない(MUST)。PC の再起動などからの復帰を想定し、再開も開始と同じペアリングモーダルを通る。

#### Scenario: 再開の表示
- **WHEN** トーナメント進行中に PC が再起動し、トップページを開き直す
- **THEN** 該当設定に「再開」が表示され、押すとペアリング後に進行状態を引き継いだサイネージが開く

#### Scenario: 設定の複製
- **WHEN** 一覧で設定の「複製」を押す
- **THEN** 「(元の名前) のコピー」という名前の新しい設定が作成され、一覧に表示される。同名のコピーが既にある場合はタイトルが一意になるよう連番(「(元の名前) のコピー 2」など)を付ける

#### Scenario: 削除の確認
- **WHEN** 一覧で設定の「削除」を押し、確認ダイアログで「削除する」を選ぶ
- **THEN** 該当設定が一覧と IndexedDB から削除される

#### Scenario: 削除のキャンセル
- **WHEN** 削除の確認ダイアログで「キャンセル」を選ぶ
- **THEN** 設定は削除されない

#### Scenario: 設定が存在しない場合
- **WHEN** 設定が 1 件も保存されていない状態でトップページを開く
- **THEN** 「新規タイマー作成」から追加するよう案内が表示される

### Requirement: ストラクチャーの定義
エディタ画面(`/editor`)は、トーナメントのストラクチャーをレベル単位で定義できなければならない(MUST)。各レベルには以下を設定できる:

- スモールブラインド(SB)
- ビッグブラインド(BB)
- アンティ(Ante)
- そのレベルの継続時間(分)

また、レベルの並びの任意の位置に、ブレイク(休憩、継続時間つき)とレイトレジストレーション締め切り(時間を持たないマーカー項目)を挿入できなければならない(MUST)。レイトレジストレーション締め切りは 1 つまでしか追加できない(MUST)。

ブラインドの入力は補完する: SB の変更時は BB に SB×2 を、BB の変更時は Ante に BB と同じ値を自動入力しなければならない(MUST)。逆方向(BB の変更で SB、Ante の変更で BB)には反映してはならない(MUST NOT)。

レベル行・プライズ行のセクションでは、入力中に Shift+Enter でも行を追加できるべきである(SHOULD)。ショートカットの案内はセクション内の注記として表示する。

ストラクチャーの行は、行内の要素にフォーカスがある状態で Alt(macOS では Option)+↑/↓ により上下に移動できるべきである(SHOULD)。移動後もフォーカスは移動した行に追従する。レイトレジストレーション締め切りの行には入力欄がないため、セル自体をフォーカス可能にし、フォーカス時に移動対象であることが視覚的に分かる目印を表示する。

レベルの追加時は、ストラクチャー内の直近のブラインドレベル(ブレイク等を挟んでいてもよい)の値を新しいレベルの初期値としなければならない(MUST)。ブラインドレベルがまだ存在しない場合は既定値(SB=100 / BB=200 / Ante=200 / 継続時間=20 分)を用いる。

#### Scenario: レベルの追加と編集
- **WHEN** ユーザーがレベルを追加し、SB=100 / BB=200 / Ante=200 / 継続時間=20 分を入力する
- **THEN** ストラクチャー一覧に入力どおりのレベルが表示される

#### Scenario: 直近レベルの値を引き継ぐ
- **WHEN** 最後のブラインドレベルが SB=300 / BB=600 / Ante=600 / 継続時間=15 分の状態で「レベルを追加」を押す
- **THEN** 追加されたレベルには SB=300 / BB=600 / Ante=600 / 継続時間=15 分が初期値として入る

#### Scenario: ブラインド入力の自動補完
- **WHEN** ユーザーが SB に 300 を入力する
- **THEN** BB に 600、Ante に 600 が自動入力される

#### Scenario: 逆方向には伝播しない
- **WHEN** ユーザーが Ante を 0 に変更する
- **THEN** SB と BB は変化しない

#### Scenario: Shift+Enter による行追加
- **WHEN** レベル行の入力欄にフォーカスがある状態で Shift+Enter を押す
- **THEN** 新しいレベル行が追加される

#### Scenario: ショートカットによる行の移動
- **WHEN** レベル行の入力欄にフォーカスがある状態で Alt+↓ を押す
- **THEN** その行が 1 つ下に移動し、フォーカスは移動した行の同じ入力欄に残る

#### Scenario: レイトレジストレーション行の移動
- **WHEN** レイトレジストレーション締め切り行のセルをクリックまたは Tab でフォーカスし、Alt+↑ を押す
- **THEN** セルに移動対象を示す目印が表示され、その行が 1 つ上に移動する

#### Scenario: ブレイクの挿入
- **WHEN** ユーザーがレベル 4 とレベル 5 の間にブレイク(10 分)を挿入する
- **THEN** ストラクチャー一覧の該当位置にブレイクが表示される

#### Scenario: レイトレジストレーション締め切りの挿入
- **WHEN** ユーザーがレベル 6 とレベル 7 の間にレイトレジストレーション締め切りを挿入する
- **THEN** ストラクチャー一覧の該当位置に締め切りマーカーが表示され、設定に保存される

#### Scenario: 締め切りは 1 つまで
- **WHEN** ストラクチャーに締め切りマーカーが既に存在する
- **THEN** 「レイトレジストレーションを追加」は実行できない

### Requirement: ストラクチャーのテンプレート
エディタ画面は、ストラクチャーをテンプレートから自動生成できなければならない(MUST)。テンプレートはハイパーターボ(レベル 5 分)・ターボ(10 分)・レギュラー(15 分)・ロング(20 分)の 4 種類を提供する。

店舗によって使用チップが異なり開始ブラインドがまちまちであるため、テンプレートはブラインドの絶対値を持たず、ユーザーが入力した開始 SB(既定値 100)に倍率を掛けてレベルを生成しなければならない(MUST)。各レベルは BB=SB×2、Ante=BB とし、SB は一般的なストラクチャーの上がり幅(約 1.3〜2 倍刻み)で単調増加させる。

テンプレートはブラインドレベルだけでなく、一定レベルごとのブレイクと、レイトレジストレーション締め切りマーカー(1 つ)も含めて生成しなければならない(MUST)。締め切りマーカーがレベルとレベルの間に単独で置かれる運用は稀であるため、必ずいずれかのブレイクの直後に配置しなければならない(MUST)。

テンプレートの適用は既存のストラクチャーを丸ごと置き換える。適用前に確認ダイアログを表示しなければならない(MUST)。開始 SB が正の数でない場合、テンプレートは適用できない(MUST NOT)。

#### Scenario: テンプレートの適用
- **WHEN** 開始 SB に 100 を入力し「ターボ」を押して確認する
- **THEN** ストラクチャーが SB=100/BB=200/Ante=200・10 分から始まる一連のレベル(ブレイク・レイトレジ締切込み)に置き換わる

#### Scenario: 開始 SB によるスケール
- **WHEN** 開始 SB に 25 を入力してテンプレートを適用する
- **THEN** 各レベルのブラインドが開始 SB=100 の場合の 1/4 になる

#### Scenario: 適用のキャンセル
- **WHEN** テンプレートのボタンを押し、確認ダイアログでキャンセルする
- **THEN** 既存のストラクチャーは変更されない

### Requirement: トーナメント情報の設定
エディタ画面は、以下のトーナメント情報を設定できなければならない(MUST)。店名は設定に含まれない(「店舗情報(店名)の管理」を参照):

- トーナメントタイトル
- プライズ(賞金)一覧(順位と内容)

参加費やチップ量(スターティングスタック、アドオン等)は設定として構造化しない(blind-timer-mvp の design.md D11 / D16 参照)。エントリー / アドオンのチップ量は、記録時にリモコンから入力する。エントリー案内(自由テキスト)は 2026-08-06 に廃止し、設定項目に含めてはならない(MUST NOT。blind-timer-mvp の design.md D16 参照)。

#### Scenario: 基本情報の入力
- **WHEN** ユーザーがトーナメントタイトル・プライズ一覧を入力する
- **THEN** 入力内容が設定として保持される

### Requirement: 設定の保存と再利用
エディタ画面は、設定を IndexedDB に保存しなければならない(MUST)。保存済み設定はトップページの一覧から「編集」で開いて編集・再保存ができ、繰り返しのトーナメント運営で再利用できなければならない(MUST)。一覧・複製・削除はトップページが担う(「トップページの設定一覧」を参照)。

#### Scenario: 設定の保存
- **WHEN** ユーザーが設定を保存する
- **THEN** 設定が IndexedDB に永続化され、ブラウザをリロードしても失われない

#### Scenario: 保存済み設定の再利用
- **WHEN** ユーザーがトップページの一覧で設定の「編集」を選ぶ
- **THEN** その設定がエディタに読み込まれた状態で開き、編集・再保存できる

### Requirement: 設定のエクスポート / インポート
トーナメント設定をファイルとしてエクスポート / インポートできなければならない(MUST)。用途はバックアップ(全件)と、別 PC・別スタッフへの共有(1 件)である。

ファイル形式は 1 件でも全件でも同じ「複数入り」の JSON 形式で統一しなければならない(MUST):

```json
{
  "app": "poker-blind-timer",
  "formatVersion": 1,
  "exportedAt": 1754600000000,
  "configs": [{ "title": "...", "prizes": [], "structure": [] }]
}
```

- `formatVersion` を必ず含め、将来のスキーマ変更時にインポート側で変換できるようにする(MUST)
- 対象は設定(`configs`)のみとし、進行中セッションや店舗名などの端末固有の状態を含めてはならない(MUST NOT)。設定の `id` / `createdAt` / `updatedAt` も端末固有の値のため含めない

UI はトップページに置く:

- 「すべてエクスポート」(バックアップ用)。ファイル名は日付入り(例: `blind-timer-configs-2026-08-08.json`)
- 各設定の「エクスポート」(共有用)。ファイル名はタイトル由来
- インポートの入口は 1 つで、1 件 / 全件どちらのファイルも読み込める(MUST)

インポート時の挙動:

- 常に新規として追加し、`id` は振り直さなければならない(MUST)。既存設定の上書きによるデータ消失を起こしてはならない(MUST NOT)
- `createdAt` / `updatedAt` はインポート時刻で振り直し、一覧(更新順)の先頭に表示する(MUST)
- タイトルの一意制約と衝突する場合は連番を付けて回避する(MUST)
- 読み込み時にバリデーション(`app` / `formatVersion` の確認、`structure` 各項目の形と値のチェック)を行い、壊れたファイルは明確なエラーメッセージで弾かなければならない(MUST)。エラー時は何も保存しない

#### Scenario: 全件エクスポート
- **WHEN** トップページで「すべてエクスポート」を押す
- **THEN** 保存済みの全設定を含む JSON ファイルが日付入りのファイル名でダウンロードされる

#### Scenario: 1 件エクスポート
- **WHEN** 一覧で設定の「エクスポート」を押す
- **THEN** その設定 1 件を含む JSON ファイルがタイトル由来のファイル名でダウンロードされる

#### Scenario: インポートは新規追加
- **WHEN** エクスポートファイルをインポートする
- **THEN** ファイル内の設定が新しい `id` で追加され、一覧の先頭に表示される。既存の設定は変更されない

#### Scenario: タイトル衝突時の連番
- **WHEN** 既存設定と同じタイトルの設定をインポートする
- **THEN** タイトルに連番(「(タイトル) 2」など)が付いた新規設定として追加される

#### Scenario: 壊れたファイルの拒否
- **WHEN** 他アプリの JSON や形式の壊れたファイルをインポートしようとする
- **THEN** 原因が分かるエラーメッセージが表示され、何も保存されない

### Requirement: 設定の検証
エディタ画面は、タイマーとして成立しない設定の保存を防がなければならない(MUST)。少なくとも以下を検証する: トーナメントタイトルが入力されていること(空白のみは不可)、レベルが 1 つ以上存在すること、SB/BB/継続時間が正の数であること、レイトレジストレーション締め切りマーカーが 1 つ以下であること。

トーナメントタイトルは保存済み設定の間で一意でなければならない(MUST)。前後の空白を除いて比較し、他の設定と同じタイトルの保存はエラーにする(編集中の設定自身との一致は重複とみなさない)。タイトルは前後の空白を取り除いた形で保存する。

#### Scenario: 不正な値の拒否
- **WHEN** ユーザーが継続時間 0 分のレベルを保存しようとする
- **THEN** エラーが表示され、保存されない

#### Scenario: タイトル未入力の拒否
- **WHEN** トーナメントタイトルが空(または空白のみ)の状態で保存しようとする
- **THEN** タイトルの入力を促すエラーが表示され、保存されない

#### Scenario: 同名タイトルの拒否
- **WHEN** 既に保存されている設定と同じトーナメントタイトルで別の設定を保存しようとする
- **THEN** 同名のタイマーがある旨のエラーが表示され、保存されない

#### Scenario: 既存設定の再保存
- **WHEN** 保存済みの設定を編集で開き、タイトルを変えずに再保存する
- **THEN** 自分自身との同名は重複とみなされず、保存に成功する
