# remote-control: リモコン(スマホ操作)

## Purpose

運営者がスマホから操作するリモコン画面の接続・タイマー操作・状態表示を定める。

## Requirements

### Requirement: リモコン画面の接続
リモコン画面(`/remote`)は、URL のチャンネル識別子(`?ch=<id>`)を用いて対応する Ably チャンネルに接続しなければならない(MUST)。チャンネル識別子がない、または接続に失敗した場合は、その旨を表示しなければならない(MUST)。

#### Scenario: QR コード経由の接続
- **WHEN** サイネージが表示した QR コードをスマホで読み取り、リモコン URL を開く
- **THEN** リモコンがサイネージと同じチャンネルに接続し、操作可能になる

#### Scenario: チャンネル識別子がない場合
- **WHEN** `?ch=` パラメータなしで `/remote` を開く
- **THEN** サイネージの QR コードから開くよう案内が表示される

### Requirement: タイマー操作
リモコン画面から以下の操作ができ、それぞれ対応するコマンドをチャンネルへ publish しなければならない(MUST):

- トーナメント開始(`START`)— サイネージが待機画面のときに開始を指示する
- エントリーの記録(`HISTORY_ADD` / `entry`)— リバイ / 再エントリーもエントリーとして記録する
- バストの記録(`HISTORY_ADD` / `bust`)
- アドオンの記録(`HISTORY_ADD` / `addon`)
- 履歴の修正・削除(`HISTORY_UPDATE` / `HISTORY_DELETE`、id 指定)
- 一時停止 / 再開(`PAUSE` / `RESUME`)
- 次のブラインドへ進む / 前のブラインドへ戻る(`NEXT_LEVEL` / `PREV_LEVEL`)
- 残り時間の変更(`SET_REMAINING`、ミリ秒指定)— 進行中レベルの残り時間をスライダーで指定した値に変更する。スライダーの最大値には状態スナップショットの `levelDurationMs`(現在レベルの持ち時間)を用いる

エントリー / アドオンの記録時、チップ量はリモコンで入力した値を記録しなければならない(MUST)。設定側にデフォルトのチップ量は持たない(blind-timer-mvp の design.md D11 / D12 参照)。記録後、チップ量の入力欄は空に戻さなければならない(MUST。前回値の残留による誤記録を防ぐ)。トーナメントタイトルの変更機能は持たない(2026-07-31 廃止決定)。

#### Scenario: 一時停止と再開
- **WHEN** リモコンで一時停止ボタンを押す
- **THEN** サイネージのタイマーが一時停止し、リモコンの表示も一時停止中になる

#### Scenario: エントリーの記録
- **WHEN** リモコンでチップ量 25000 を入力して「エントリー」を押す
- **THEN** サイネージの Total Entries と Current Players が 1 増え、25000 がチップ量として履歴に記録される

#### Scenario: バストの記録
- **WHEN** リモコンで「バスト」を押す
- **THEN** サイネージの Current Players が 1 減り、Total Entries は変化しない

#### Scenario: 残り 2 人でのバスト確認
- **WHEN** 現在プレイヤー数が 2 人のときにリモコンで「バスト」を押す
- **THEN** 優勝を決定する操作であり取り消せない旨の確認ダイアログが表示され、承諾した場合のみバストが記録される

#### Scenario: トーナメント終了後の表示
- **WHEN** 優勝の確定などでトーナメントが終了した状態スナップショットを受信する
- **THEN** トーナメントが終了した旨の画面に切り替わり、以降の操作はできない。リモコンは Ably 接続を切断する

#### Scenario: チップ量の指定
- **WHEN** リモコンでチップ量を 30000 と入力してアドオンを記録する
- **THEN** 履歴には 30000 のアドオンが記録され、平均チップに反映される

#### Scenario: レベル移動
- **WHEN** リモコンで「次のブラインドへ」を押す
- **THEN** サイネージが次のレベルへ切り替わる

#### Scenario: 残り時間の変更
- **WHEN** タイマー進行中にリモコンの残り時間スライダーで 12:00 を指定する
- **THEN** サイネージの残り時間が 12:00 になり、そこからカウントダウンが継続する

### Requirement: 現在状態の表示
リモコン画面は、サイネージから受信した状態スナップショットに基づき、現在のタイマー状態(残り時間、現在レベルのブラインド、一時停止中かどうか、プレイヤー数、アドオン数)を表示しなければならない(MUST)。接続直後は最新状態を要求(`REQUEST_STATE`)して表示を同期し、初回スナップショットを受信するまで要求を再送しなければならない(MUST。接続直後にスナップショットが届かない競合への対策)。待機中は最初のブラインドとそのレベルの持ち時間を表示する。

#### Scenario: 履歴一覧の表示と修正
- **WHEN** リモコンで履歴一覧を開く
- **THEN** 状態スナップショットに含まれる履歴(種別・チップ量)が新しい順に表示され、各履歴に対して修正(チップ量変更)・削除を実行できる

#### Scenario: 接続直後の状態同期
- **WHEN** タイマー進行中にリモコンが接続する
- **THEN** リモコンに現在の残り時間・レベル・人数が表示される

#### Scenario: 再接続時の復帰
- **WHEN** リモコンの通信が一時的に切断された後、再接続する
- **THEN** リモコンの表示が最新状態へ復帰する

#### Scenario: 切断中の操作防止
- **WHEN** リモコンの通信が切断され、短時間で復帰しない
- **THEN** 再接続中である旨のモーダルが表示され、切断に気づかないまま操作することができなくなる。再接続が完了するとモーダルは自動的に閉じ、操作を再開できる

#### Scenario: スクロール時のコンパクト表示
- **WHEN** コントロールタブで下にスクロールし、現在状態の表示(残り時間・ブラインド)が画面外に出る
- **THEN** 画面上部にレベル・残り時間・ブラインドのコンパクトバーが固定表示され、スクロール位置に関わらず現在状態を確認できる

### Requirement: ストラクチャーの編集
リモコン画面は、実行中トーナメントのストラクチャーを閲覧・編集する画面を提供しなければならない(MUST)。編集画面は状態スナップショットの実効ストラクチャー(`structure`)と現在位置(`currentIndex`)をもとに構成する。

- 進行中および通過済みの項目(ブラインド・ブレイク・レイトレジ締切マーカー)は表示のみとし、編集できてはならない(MUST NOT)。現在進行中の項目は識別できるように表示する
- 現在位置より後ろ(未来)の項目は、値の変更(ブラインドの SB / BB / Ante / 継続時間、ブレイクの継続時間)・追加(ブラインド / ブレイク / レイトレジ締切=ストラクチャー内に未設置の場合のみ)・削除ができなければならない(MUST)
- 開始前(`waiting`)は全項目を編集できる
- 編集はローカルのドラフトに対して行い、「適用」操作と確認ダイアログを経て初めて `STRUCTURE_UPDATE` コマンド(編集後のストラクチャー全量)を publish しなければならない(MUST)。適用前の検証エラー(ブラインド 0 件、レイトレジ締切の重複、不正な数値)はその場で表示し、送信しない
- 未到達のレイトレジ締切マーカーを削除する際は、締め切りが無くなり優勝・インマネの確定条件が変わる旨を警告しなければならない(MUST)

適用の成否は送信後の状態スナップショットで判定する: 受信したストラクチャーが送信内容と一致すれば適用成功として編集画面を閉じ、一致しなければタイマーの進行と競合した旨を表示し、受信した最新のストラクチャーで編集画面を更新しなければならない(MUST)。

#### Scenario: 未来のレベルの変更
- **WHEN** レベル 3 進行中に、リモコンの編集画面でレベル 5 の継続時間を 20 分から 15 分に変更して「適用」し、確認ダイアログを承諾する
- **THEN** `STRUCTURE_UPDATE` が publish され、適用後のスナップショットを受信して編集画面が閉じ、サイネージの NEXT BREAK などの表示が新しいストラクチャーで再計算される

#### Scenario: 進行中・過去の項目のロック
- **WHEN** レベル 3 進行中に編集画面を開く
- **THEN** レベル 1〜2 と通過済みのブレイク・レイトレジ締切、および進行中のレベル 3 は編集不可として表示され、レベル 4 以降のみ編集できる

#### Scenario: 適用時の競合
- **WHEN** リモコンが編集している間にサイネージ側でレベルが自動遷移し、遷移後の現在項目を変更する内容の「適用」が拒否される
- **THEN** リモコンはタイマーの進行と競合した旨を表示し、編集画面を受信した最新のストラクチャーと現在位置で更新する

#### Scenario: 送信前の検証エラー
- **WHEN** ドラフトで未来のブラインドの SB を 0 にして「適用」を押す
- **THEN** エラーが表示され、`STRUCTURE_UPDATE` は送信されない

### Requirement: 状態スナップショットのストラクチャー情報
状態スナップショットには、実効ストラクチャー(セッション限定の上書き適用後)の全量 `structure` と、解決済みの現在項目 index `currentIndex`(`waiting` / `finished` のときは null)を含めなければならない(MUST)。

#### Scenario: スナップショットからの編集画面構成
- **WHEN** リモコンが状態スナップショットを受信して編集画面を開く
- **THEN** スナップショットの `structure` が一覧表示され、`currentIndex` までの項目がロックされる

### Requirement: スマホ向け操作 UI
リモコン画面はスマホの縦持ち・片手操作を前提とし、タップ対象は誤タップしにくい十分な大きさを確保しなければならない(MUST)。レベル移動や履歴の削除などの影響が大きい操作は、頻繁に使う操作(エントリー・バストの記録など)と視覚的に分離して配置しなければならない(MUST)。画面は接続の状態(接続中 / 待機 / 進行中 / 終了)に応じて切り替え、進行中の操作はコントロール / ストラクチャー / 履歴のタブで整理する。トーナメント開始は誤操作を防ぐためスライド操作としなければならない(MUST)。

#### Scenario: スマホでの表示
- **WHEN** スマホ相当の画面幅でリモコン画面を開く
- **THEN** すべての操作ボタンが片手で届く配置・大きさで表示される
