# signage-display: サイネージ(タイマー本体)

## Purpose

プレイヤー向け大画面表示(サイネージ)の画面構成・タイマー進行・演出・統計表示・状態の永続化を定める。

## Requirements

### Requirement: 画面構成と状態遷移
サイネージ(`/signage`)は次の 4 画面を持たなければならない(MUST):

- **待機画面**: プレイヤー・ディーラーの準備を待つ間の表示。リモコンの開始操作まで表示する
- **タイマー画面**: ブラインドレベル進行中の表示
- **ブレイク画面**: ストラクチャーのブレイク項目中の表示
- **優勝画面**: 優勝確定後の表示

画面は次のように遷移しなければならない(MUST):

- リモコンの開始操作(トーナメント開始)で開始演出を再生し、**再生開始から 7 秒後にタイマー画面へ遷移、8 秒後にタイマーが動き出す**(タイマーの基準時刻 = 再生開始+8 秒)。演出素材が無い・再生に失敗した・動画が 8 秒未満で終わった場合は、その時点で即座にタイマーを開始する
- ストラクチャー上のブレイクに入るとブレイク画面、ブレイクが終わるとタイマー画面へ戻る
- 優勝が確定(現在プレイヤー数が 1 人)すると優勝演出を再生し、**再生開始から 7 秒後に優勝画面へ遷移する**。演出素材が無い・再生に失敗した・動画が 7 秒未満で終わった場合は、その時点で即座に遷移する
- 優勝確定は履歴からの導出であり、履歴の修正で現在プレイヤー数が 2 人以上に戻った場合は優勝画面から復帰しなければならない(MUST)

#### Scenario: 開始操作でタイマー画面へ
- **WHEN** 待機画面の表示中にリモコンから開始操作を受信し、開始演出の再生が始まる
- **THEN** 再生開始から 7 秒後にタイマー画面へ切り替わり(タイマーは 8 秒後までフルタイム表示)、8 秒後にレベル 1 のカウントダウンが進行を始める

#### Scenario: ブレイクへの切り替え
- **WHEN** 現在レベルが終了しストラクチャー上のブレイクに入る
- **THEN** ブレイク画面に切り替わり、ブレイク終了で次のレベルのタイマー画面へ戻る

#### Scenario: 優勝の確定と復帰
- **WHEN** バストの記録で現在プレイヤー数が 1 人になる
- **THEN** 優勝演出の後に優勝画面が表示される。誤操作でそのバストが削除され 2 人に戻った場合はタイマー画面へ復帰する

### Requirement: 待機画面の表示
待機画面は、店名(店舗情報)・トーナメントタイトル・最初のブラインド(SB / BB / Ante)を表示しなければならない(MUST)。デザインはチップ浮遊背景モック(Three.js、黒×ゴールド、中央セーフゾーン)に準拠する。

#### Scenario: 待機画面の内容
- **WHEN** トップページの開始フローからサイネージを開く
- **THEN** 店名・トーナメントタイトル・最初の SB/BB/Ante が表示される

### Requirement: タイマー画面の表示項目
タイマー画面は、1920×1080 基準のレイアウトを画面サイズに合わせてスケーリングし、以下を表示しなければならない(MUST):

- トーナメントタイトル
- PRIZE LIST(プライズ一覧。あふれる場合は下端をフェード)
- 残り時間(中央で最も目立つ)
- 現在のレベル番号(LEVEL バッジ)
- 現在の BLINDS(SB / BB)と ANTE
- NEXT BLINDS(次のブラインドと ANTE)
- PLAYERS(現在プレイヤー数 / 総エントリー数)
- ADD-ON 数
- AVERAGE STACK
- NEXT BREAK(次のブレイクまでの残り時間と、そのブレイクの長さ)
- LATE REGISTRATION(締め切りまでの残り時間)

プレイヤー数・エントリー数・アドオン数・平均チップは、操作履歴(histories)から導出した値を表示する(「トーナメント履歴と統計の導出」を参照)。デザインはタイマー画面モック(WebGL 背景)に準拠する(モックにあった円形ゲージは 2026-08-01 に不採用を決定)。

#### Scenario: 表示項目の確認
- **WHEN** タイマー進行中にサイネージ画面を表示する
- **THEN** 上記すべての項目が表示され、残り時間が毎秒更新される

#### Scenario: レイトレジストレーション終了後の表示
- **WHEN** レイトレジストレーション締め切り位置を過ぎる
- **THEN** レイトレジストレーションの残り時間表示は終了済みであることを示す

### Requirement: タイマーの正確な進行
タイマーの経過時間は、基準時刻(エポック ms)と現在時刻の差分から算出しなければならない(MUST)。`setInterval` の実行回数に依存してはならない(MUST NOT)。タブの非アクティブ化や処理落ちが発生しても、復帰時に正しい残り時間を表示しなければならない(MUST)。レベルの残り時間が 0 になったら、自動的に次のレベル(またはブレイク)へ 1 回だけ遷移しなければならない(MUST)。レイトレジ締め切りマーカーは時間を持たず、到達時に即座に通過する。

#### Scenario: 非アクティブ後の復帰
- **WHEN** タイマー進行中にタブを 3 分間非アクティブにして戻る
- **THEN** 実際の経過時間を反映した正しい残り時間が表示される

#### Scenario: レベルの自動遷移
- **WHEN** 現在レベルの残り時間が 0 になる
- **THEN** 次のレベルへ 1 回だけ遷移し、次レベルの継続時間からカウントダウンが始まる

### Requirement: レベルアップ・一時停止の演出
レベルが進んだとき、タイマー画面はレベルアップ演出(LEVEL UP 表示 → レベル番号・ブラインドのロール切替、背景の発光ブースト)を再生しなければならない(MUST)。一時停止中は「一時停止中」のテープ演出を表示し、再開で解除しなければならない(MUST)。テープ演出はタイマー画面・ブレイク画面の両方で表示しなければならない(MUST)。演出はモックに準拠し、`prefers-reduced-motion` ではフェードのみの簡易表示に切り替えるべきである(SHOULD)。

#### Scenario: レベルアップ演出
- **WHEN** レベルが自動遷移する
- **THEN** レベルアップ演出が再生され、演出後に新しいレベル番号・ブラインドが表示される

#### Scenario: 一時停止の表示
- **WHEN** リモコンから PAUSE を受信する
- **THEN** テープ演出が表示され残り時間が固定される。RESUME で演出が解除されカウントダウンが再開する

### Requirement: 演出動画オーバーレイ
サイネージは、表示中の画面に関わらず演出動画をオーバーレイ再生できなければならない(MUST)。イベントと動画の対応は追加・差し替え可能な仕組みとし(MUST)、動画素材が未配置のイベントは演出をスキップして画面遷移のみ行う(MUST)。

自動判定するイベント(各トーナメントで 1 回だけ再生):

- **トーナメント開始**: リモコンの開始操作。再生後にタイマー画面へ
- **インマネ**: 現在プレイヤー数がプライズ件数以下になったとき
- **HEADS UP**: 現在プレイヤー数が 2 人になったとき
- **優勝**: 現在プレイヤー数が 1 人になったとき。再生後に優勝画面へ

動画は webm(映像のみ。透過可)+ ogg(音声)の 2 ファイル同時再生に統一する(MUST)。透過 webm に音声を含めると再生バグがあるため音声を分離する。開始演出を除き、動画再生はタイマー進行に影響してはならない(MUST NOT)。演出素材(動画・効果音・画像)は、再生時の待ちを避けるためサイネージ表示開始時に先読みするべきである(SHOULD)。

#### Scenario: HEADS UP 演出
- **WHEN** バストの記録で現在プレイヤー数が 2 人になる
- **THEN** HEADS UP の動画がタイマー画面の上にオーバーレイ再生され、タイマーは進行し続ける

#### Scenario: 素材未配置のイベント
- **WHEN** 動画素材が配置されていないイベントが発生する
- **THEN** 動画は再生されず、画面遷移などの動作のみ行われる

### Requirement: 効果音・アナウンスの再生
サイネージは、進行イベントに応じて音声ファイル(効果音・アナウンス)を再生できなければならない(MUST)。少なくとも以下のイベントを持つ:

- レベルアップの 10 秒前(予告音)
- レベルアップの瞬間
- ブレイク開始(アナウンス)
- 一時停止 / 再開

音声とイベントの対応は追加・差し替え可能な仕組みとし(MUST)、素材未配置のイベントは何も再生しない(MUST)。

#### Scenario: レベルアップ予告音
- **WHEN** 現在レベルの残り時間が 10 秒になる
- **THEN** 予告音が 1 回再生される

#### Scenario: ブレイク開始アナウンス
- **WHEN** ストラクチャー上のブレイクに入る
- **THEN** ブレイク開始の音声が再生される

### Requirement: トーナメント履歴と統計の導出
サイネージは、エントリー・アドオン・バストの操作を履歴(histories)として保持しなければならない(MUST)。各履歴エントリは、一意な id(サイネージが採番)、種別(`entry` | `addon` | `bust`)、チップ量(`entry` / `addon` のみ)を持つ。リバイ / 再エントリーは `entry` として記録する。

統計は履歴から導出しなければならない(MUST):

- 総エントリー数(Total Entries)= `entry` の件数
- 現在のプレイヤー数(Current Players)= `entry` の件数 − `bust` の件数
- アドオン数(Add-ons)= `addon` の件数
- 平均チップ(Average Stack)= `entry` と `addon` のチップ量の合計 ÷ 現在のプレイヤー数(プレイヤー数が 0 のときは非表示または「-」)

`entry` / `addon` のチップ量は、リモコンから記録時に指定された値を保存しなければならない(MUST)。記録済みの履歴のチップ量が(id 指定の修正以外で)後から変化してはならない(MUST NOT)。

#### Scenario: 統計の導出
- **WHEN** 履歴が entry(25000)× 3、addon(30000)× 1、bust × 1 のとき
- **THEN** Total Entries = 3、Current Players = 2、Add-ons = 1、Average Stack = (25000 × 3 + 30000) ÷ 2 = 52500 と表示される

#### Scenario: 履歴の修正・削除の反映
- **WHEN** リモコンから id 指定の履歴修正(チップ量変更)または削除コマンドを受信する
- **THEN** 該当履歴が更新・削除され、すべての統計表示が再計算される

### Requirement: 状態の永続化とリロード復元
サイネージは、トーナメント状態(現在レベル、基準時刻、一時停止状態、操作履歴、接続チャンネル ID など)の変化を IndexedDB に保存しなければならない(MUST)。ページをリロードした場合、保存された状態から進行中の画面(待機 / タイマー / ブレイク / 優勝)を復元し、保存済みチャンネル ID で Ably へ再接続しなければならない(MUST)。復元時の残り時間は、経過した実時間を反映していなければならない(MUST)。

#### Scenario: リロードによる復元
- **WHEN** タイマー進行中にサイネージのページをリロードする
- **THEN** 実時間の経過を反映した残り時間でタイマーが継続し、リモコンとの接続も回復する

#### Scenario: 一時停止中のリロード
- **WHEN** 一時停止中にページをリロードする
- **THEN** 一時停止状態と停止時点の残り時間が維持される

### Requirement: 操作コマンドの適用
サイネージは、リモコンから受信した操作コマンド(開始、一時停止 / 再開、レベル移動、残り時間の変更、履歴の記録・修正・削除、状態要求)を自身の状態に適用し、表示へ即座に反映しなければならない(MUST)。タイマー進行の正(source of truth)はサイネージ側とし、同一コマンドの重複受信で状態が破綻してはならない(MUST NOT)。チャンネルの購読を開始した直後には現在状態を publish しなければならない(MUST。リモコン接続直後の同期漏れ防止)。

#### Scenario: 一時停止コマンドの適用
- **WHEN** リモコンから PAUSE コマンドを受信する
- **THEN** タイマーが一時停止し、残り時間が固定表示される

#### Scenario: レベル移動コマンドの適用
- **WHEN** リモコンから NEXT_LEVEL コマンドを受信する
- **THEN** 次のレベルに切り替わり、そのレベルの継続時間から再スタートする
