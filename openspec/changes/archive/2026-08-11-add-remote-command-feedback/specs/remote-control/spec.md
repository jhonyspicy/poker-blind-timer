## ADDED Requirements

### Requirement: コマンド送信のフィードバック
リモコンは操作コマンドの送信を「送信 → サイネージの ACK 受信 → 完了」までを一つの処理として扱い、その進行を利用者に示さなければならない(MUST)。

- 送信を開始した時点から ACK を受信するまで、リモコンの操作を受け付けてはならない(MUST。応答が分からず同じ操作を重ねて送ってしまうのを防ぐ)
- 応答待ちが一定時間(既定 300ms)を超えた場合にのみ、送信中である旨の表示を出さなければならない(MUST)。それより早く完了した場合は送信中の表示を出してはならない(MUST NOT。通常の操作で画面がちらつくのを防ぐ)
- ACK を受信したら、短時間で自動的に消える完了表示を出さなければならない(MUST)
- 一定時間(既定 5 秒)以内に ACK を受信しない場合、または送信自体が失敗した場合は、利用者が明示的に閉じるまで消えない失敗の警告を表示しなければならない(MUST。ボタンを押した後すぐ別の作業へ移る運営でも失敗に気づけるようにするため)
- 失敗の警告からは、同じコマンドの再送と、警告を閉じることができなければならない(MUST)。再送では最初の送信と同じ `requestId` を用いなければならない(MUST。ACK だけが失われた場合にサイネージ側の重複排除が働き、二重適用を防ぐため)
- `rejected` の ACK を受信した場合は、通信の失敗ではなくサイネージが操作を受け付けない状態である旨を表示しなければならない(MUST)
- 状態の同期要求(`REQUEST_STATE`)は利用者の操作ではないため、これらの表示・ブロックの対象としてはならない(MUST NOT)
- トーナメント終了(`finished`)のスナップショットを受信した場合は、応答待ちの状態を破棄し、失敗の警告を出してはならない(MUST NOT。終了に伴う接続の終了であり失敗ではないため)

#### Scenario: 通常の送信
- **WHEN** リモコンでバストを記録し、サイネージからの ACK が 300ms 未満で返る
- **THEN** 送信中の表示は出ず、短時間で消える完了表示が出て、次の操作ができるようになる

#### Scenario: 応答が遅い場合の送信中表示
- **WHEN** リモコンで操作し、ACK の受信までに 300ms 以上かかる
- **THEN** 送信中である旨の表示が出て、ACK を受信すると完了表示に切り替わる

#### Scenario: 応答待ち中の連打の防止
- **WHEN** ACK を受信する前に同じボタンを続けてタップする
- **THEN** 2 回目以降のタップは受け付けられず、コマンドは 1 回だけ送信される

#### Scenario: 送信の失敗
- **WHEN** サイネージが停止しているなどの理由で、5 秒経っても ACK が返らない
- **THEN** 送信できなかった旨の警告が表示され、利用者が「再送」または「閉じる」を選ぶまで表示され続ける

#### Scenario: 失敗からの再送
- **WHEN** 失敗の警告で「再送」を選ぶ
- **THEN** 同じ `requestId` で同じコマンドが再送され、応答待ちの状態に戻る

#### Scenario: 受け付けられない操作
- **WHEN** サイネージが優勝確定後の状態で、リモコンの操作に対し `rejected` の ACK が返る
- **THEN** 操作を受け付けられない状態である旨が表示される
