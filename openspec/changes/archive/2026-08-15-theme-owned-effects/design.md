## Context

現状、サイネージの演出は次の 3 箇所で「動画である」ことが共有層に固定されている。

- `SignagePage.tsx` が `VideoOverlay`(webm + ogg)を直接マウントする
- `useSignageController.ts` が `START_SCREEN_DELAY_MS`(7 秒)/ `START_TIMER_DELAY_MS`(8 秒)/ `CHAMPION_SCREEN_DELAY_MS`(7 秒)を持ち、演出の `onStarted` を起点に `setTimeout` で画面遷移とタイマー起動を行う
- `preload.ts` が素材リスト(動画 4 種 × 2 拡張子・効果音 5 種・画像 1 種)をハードコードしており、テーマが持たない素材にも取得を試みる

一方で、イベントの検知(インマネ・HEADS UP・優勝の判定)は `applyMilestones` に分離されており、演出キューに積む形になっている。**「何が起きたか」と「どう見せるか」の分離は既に半分できており、欠けているのは後者をテーマへ渡す口だけ**である。

制約:

- 標準テーマは実店舗で稼働中。見た目・素材・タイミングを変えない(ちょい見せ廃止を除く)
- タイマーの正確性と、演出の失敗でトーナメントが止まらないことが最優先(AGENTS.md 2 章)
- 保存済みデータ(`SessionState.playedEffects`)との互換を壊さない

## Goals / Non-Goals

**Goals:**

- テーマが演出の実装方式(動画 / 静止画 / CSS / なし)とタイミングを自分で決められるようにする
- テーマが持たない素材を取りに行かないようにする
- 演出が応答しなくても、トーナメントの進行が必ず先へ進むことを共有層で保証する
- 標準テーマの挙動を(ちょい見せを除いて)変えない

**Non-Goals:**

- 軽量テーマそのものの追加(本チェンジは土台のみ)
- 標準テーマの性能改善(動画の再エンコード、一時停止演出の最適化)
- 利用者アップロード画像・テーマ別の設定項目・イベントの追加(`final-table` 等)
- 効果音の仕組みの変更

## Decisions

### D1: 合図は `onAdvance` / `onDone` の 2 つに絞る

演出 → 共有層の合図を次の 2 つとする。

- `onAdvance()`: このイベントのドメインへの影響を進めてよい。`tournament-start` ならタイマー起動、`champion` なら優勝画面への遷移。それ以外のイベントでは無視される
- `onDone()`: 演出の終了。オーバーレイを外し、キューの次へ進む

**なぜ合図の種類を分けないか**: 当初は `timer-screen` / `timer-start` / `champion-screen` の 3 種を検討したが、`START_TIMER_DELAY_MS` の廃止により「画面遷移」と「タイマー起動」が同時になり、イベントごとに意味のある合図は 1 つだけになる。種類を持たせると、イベントと合図の有効な組み合わせを共有層が知る必要があり、テーマ追加のたびに検証が増える。

**代替案**: 演出が「自分の総尺」を宣言し、共有層が `setTimeout` を張る。却下 — 動画の実尺は再生してみないと分からず、CSS 演出は宣言と実装がずれ得る。現行の `onStarted` ベースの設計が既にこの問題を回避しており、その延長にする。

### D2: タイミングはテーマが持つ

`START_SCREEN_DELAY_MS` / `START_TIMER_DELAY_MS` / `CHAMPION_SCREEN_DELAY_MS` を共有層から削除し、演出コンポーネントが自分で `onAdvance` を呼ぶ時刻を決める。標準テーマの動画演出は「再生開始の 7 秒後」を内部に持つ。

**`START_TIMER_DELAY_MS` の廃止**: 2 本の定数がずれると「タイマー画面が出たのにカウントダウンが始まらない」状態が延び、不整合として見える。1 秒差が生む「ちょい見せ」は演出としては軽微で、必要なら演出コンポーネントが自分の中で静止画として表現できる(共有層の 2 段階遷移に頼る必要がない)。

### D3: `earlyTimerScreen` を削除する

`START_TIMER_DELAY_MS` の廃止により、タイマー起動と同時に `TimerState.status` が `waiting` → `running` へ変わるため、`phase` の算出はタイマー状態だけで決まる。開始演出中だけ画面を先送りする `earlyTimerScreen` state と、`TimerScreen` の `waitingPreview` 分岐は不要になり、削除する。

これは状態の重複(タイマー状態と画面フラグが両方 "開始したか" を持つ)の解消でもあり、AGENTS.md 6 章の「複数の Boolean で状態を表現しない」方針に沿う。

### D4: 素材宣言はテーマディレクトリ起点の相対パス配列

```ts
assets?: readonly string[]  // 例: ['videos/champion.webm', 'sounds/level-up.ogg']
```

先読みはこの配列だけを見る。イベント名から拡張子を組み立てる現行の推論をやめ、テーマが実際に持つファイルだけを列挙する。

**代替案**: 構造化した宣言(`{ videos: [...], sounds: [...], images: [...] }`)。却下 — 先読みは URL を取得するだけでカテゴリを区別しておらず、構造を持たせても使い道がない。将来 R2 等へ移す際も、パス解決は `themeAssetPath()` の 1 箇所に閉じたままにできる。

**効果音は宣言の対象だが、再生経路は変更しない**: `playSound()` は素材が無ければ無音でスキップする実装のままとする。宣言は先読みのためだけに使う。テーマごとに鳴らすイベントを絞る仕組みは、必要になるまで作らない(MVP 方針)。

### D5: 演出タイムアウトは共有層の保険として必ず張る

演出が `onAdvance` / `onDone` を返さないまま一定時間が過ぎたら、共有層が両方を肩代わりして次へ進める。既定 20 秒、テーマが `effectTimeoutMs` で上書きできる。

**なぜ `onDone` だけでなく `onAdvance` も肩代わりするか**: `onAdvance` を取りこぼすとトーナメントが永久に開始しない。テーマの実装ミスや低速環境がトーナメント運営を止めることは許容できない。

**既定値の根拠**: 標準テーマの動画は最長 10.1 秒。20 秒あれば正常系を切らず、低速環境で画面が長時間覆われる事態(実測 90 秒)は防げる。

**現行のウォッチドッグとの関係**: `VideoOverlay` 内の「5 秒間 `currentTime` が進まなければ終了」は動画固有の停滞検知として標準テーマ側に残す。共有層のタイムアウトは実装方式に依らない上限として別に張る。

### D6: イベント型は `src/pages/signage/events.ts` に置く

`VideoOverlay.tsx` が持っている `VideoEvent` を `EffectEvent` に改名して切り出し、共有層とテーマの共通語彙にする。`domain/` ではなく `pages/signage/` に置くのは、これがサイネージの表示イベントであってドメインモデルではないため(AGENTS.md 7 章)。

`SessionState.playedEffects` は現状 `string[]` でユニオン型に依存していないため、イベントを増減しても保存済みデータとの互換は保たれる。この緩さは維持する。

### D7: `VideoOverlay` は標準テーマ配下へ移す

`src/pages/signage/VideoOverlay.tsx` → `src/pages/signage/themes/default/VideoEffectOverlay.tsx`(CSS モジュールも同様)。webm + ogg の 2 ファイル同時再生は共有層の仕様ではなく標準テーマの実装詳細になる。

## Risks / Trade-offs

- **テーマが `onAdvance` を呼ばず、トーナメントが開始しない** → D5 のタイムアウトが `onAdvance` も肩代わりする。加えて、演出が `onDone` を先に呼んだ場合も `onAdvance` を補完する(現行の「素材なしなら即開始」と同じ扱い)
- **タイムアウトが正常な演出を途中で切る** → 既定 20 秒は標準テーマの最長動画(10.1 秒)の約 2 倍。長い演出を持つテーマは `effectTimeoutMs` で延ばせる
- **ちょい見せの廃止で開始演出の見え方が変わる** → 7 秒時点でタイマー画面が現れてすぐ動き出す形になる。利用者に見える変化のため `updates.ts` に追記する
- **リファクタリング範囲がサイネージ全体に及ぶ** → 保存データ形式・同期プロトコル・リモコンには一切触れない。検証は既存テスト(`domain/` 配下)+ サイネージの手動確認(AGENTS.md 10 章のチェック項目)で行う
- **手動確認に依存する** → サイネージの画面遷移・演出には自動テストが無く、本チェンジでも追加しない。開始 / ブレイク / 優勝 / リロード復元を手動で確認する

## Migration Plan

保存データ・URL・同期プロトコルに変更が無いため、移行手順は不要。デプロイ後のリロードでそのまま新実装に切り替わる。ロールバックは revert のみで完結する。

## Open Questions

なし。軽量テーマの具体的な演出内容・標準テーマの性能改善は本チェンジのスコープ外として別途扱う。
