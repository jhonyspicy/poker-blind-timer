# signage-display: サイネージ(タイマー本体)

## ADDED Requirements

### Requirement: 保存済み設定からのタイマー起動
サイネージ画面(`/signage`)は、同一ブラウザの IndexedDB に保存された設定を読み込んでタイマーを開始できなければならない(MUST)。設定が存在しない場合は、エディタへの案内を表示しなければならない(MUST)。

#### Scenario: 設定を読み込んで起動
- **WHEN** エディタで設定を保存した後、同じブラウザで `/signage` を開く
- **THEN** 保存した設定のトーナメント情報とストラクチャーでタイマーが表示される

#### Scenario: 設定が存在しない場合
- **WHEN** 設定が保存されていないブラウザで `/signage` を開く
- **THEN** エディタで設定を作成するよう案内が表示される

### Requirement: タイマーの正確な進行
タイマーの経過時間は、基準時刻(エポック ms)と現在時刻の差分から算出しなければならない(MUST)。`setInterval` の実行回数に依存してはならない(MUST NOT)。タブの非アクティブ化や処理落ちが発生しても、復帰時に正しい残り時間を表示しなければならない(MUST)。レベルの残り時間が 0 になったら、自動的に次のレベル(またはブレイク)へ 1 回だけ遷移しなければならない(MUST)。

#### Scenario: 非アクティブ後の復帰
- **WHEN** タイマー進行中にタブを 3 分間非アクティブにして戻る
- **THEN** 実際の経過時間を反映した正しい残り時間が表示される

#### Scenario: レベルの自動遷移
- **WHEN** 現在レベルの残り時間が 0 になる
- **THEN** 次のレベルへ 1 回だけ遷移し、次レベルの継続時間からカウントダウンが始まる

#### Scenario: 最終レベルの終了
- **WHEN** ストラクチャー最後のレベルの残り時間が 0 になる
- **THEN** タイマーは終了状態(finished)となる

### Requirement: サイネージ表示項目
サイネージ画面は、以下の項目を大画面向けレイアウトで表示しなければならない(MUST):

- お店の名前
- トーナメントタイトル
- プライズ一覧
- 現在のブラインド(SB / BB / Ante)
- 現在のレベルの残り時間(画面中央で最も目立つ)
- 次のブラインド(SB / BB / Ante)
- 現在のプレイヤー数(Current Players)
- 総エントリー数(Total Entries)
- アドオン数(Add-ons)
- 平均チップ(Average Stack)
- 次のブレイクまでの残り時間
- レイトレジストレーション終了までの残り時間

プレイヤー数・エントリー数・アドオン数・平均チップは、操作履歴(histories)から導出した値を表示する(「トーナメント履歴と統計の導出」を参照)。

#### Scenario: 表示項目の確認
- **WHEN** タイマー進行中にサイネージ画面を表示する
- **THEN** 上記すべての項目が表示され、残り時間が毎秒更新される

#### Scenario: ブレイク中の表示
- **WHEN** ストラクチャー上のブレイクに到達する
- **THEN** ブレイク中であることと、ブレイク終了までの残り時間が表示される

#### Scenario: レイトレジストレーション終了後の表示
- **WHEN** レイトレジストレーション締め切り位置を過ぎる
- **THEN** レイトレジストレーションの残り時間表示は終了済みであることを示す

### Requirement: トーナメント履歴と統計の導出
サイネージは、エントリー・アドオン・バストの操作を履歴(histories)として保持しなければならない(MUST)。各履歴エントリは、一意な id(サイネージが採番)、種別(`entry` | `addon` | `bust`)、チップ量(`entry` / `addon` のみ)を持つ。リバイ / 再エントリーは `entry` として記録する。

統計は履歴から導出しなければならない(MUST):

- 総エントリー数(Total Entries)= `entry` の件数
- 現在のプレイヤー数(Current Players)= `entry` の件数 − `bust` の件数
- アドオン数(Add-ons)= `addon` の件数
- 平均チップ(Average Stack)= `entry` と `addon` のチップ量の合計 ÷ 現在のプレイヤー数(プレイヤー数が 0 のときは非表示または「-」)

チップ量が指定されなかった `entry` / `addon` には、設定のスターティングスタック / アドオンのチップ量を記録時の値として保存しなければならない(MUST)。設定を後から変更しても、記録済みの履歴のチップ量は変化してはならない(MUST NOT)。

#### Scenario: 統計の導出
- **WHEN** 履歴が entry(25000)× 3、addon(30000)× 1、bust × 1 のとき
- **THEN** Total Entries = 3、Current Players = 2、Add-ons = 1、Average Stack = (25000 × 3 + 30000) ÷ 2 = 52500 と表示される

#### Scenario: 履歴の修正・削除の反映
- **WHEN** リモコンから id 指定の履歴修正(チップ量変更)または削除コマンドを受信する
- **THEN** 該当履歴が更新・削除され、すべての統計表示が再計算される

### Requirement: 状態の永続化とリロード復元
サイネージは、タイマー状態(現在レベル、基準時刻、一時停止状態、操作履歴(histories)など)の変化を IndexedDB に保存しなければならない(MUST)。ページをリロードした場合、保存された状態から進行中のタイマーを復元しなければならない(MUST)。復元時の残り時間は、経過した実時間を反映していなければならない(MUST)。

#### Scenario: リロードによる復元
- **WHEN** タイマー進行中にサイネージのページをリロードする
- **THEN** 実時間の経過を反映した残り時間でタイマーが継続する

#### Scenario: 一時停止中のリロード
- **WHEN** 一時停止中にページをリロードする
- **THEN** 一時停止状態と停止時点の残り時間が維持される

### Requirement: 操作コマンドの適用
サイネージは、リモコンから受信した操作コマンドを自身の状態に適用し、表示へ即座に反映しなければならない(MUST)。タイマー進行の正(source of truth)はサイネージ側とし、同一コマンドの重複受信で状態が破綻してはならない(MUST NOT)。

#### Scenario: 一時停止コマンドの適用
- **WHEN** リモコンから PAUSE コマンドを受信する
- **THEN** タイマーが一時停止し、残り時間が固定表示される

#### Scenario: レベル移動コマンドの適用
- **WHEN** リモコンから NEXT_LEVEL コマンドを受信する
- **THEN** 次のレベルに切り替わり、そのレベルの継続時間から再スタートする
